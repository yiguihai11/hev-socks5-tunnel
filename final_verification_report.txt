1. 问题描述
───────────
用户反馈: "好像是压缩指针的问题还有cname问题"

原始函数 hev_dns_latency_modify_response() 的问题:
- 只保留目标Answer，删除其他所有Answer
- 如果存在CNAME记录，删除CNAME会导致后续A记录的压缩指针失效
- 破坏DNS响应结构，客户端无法解析

2. 测试数据构建
────────────────
场景: www.example.com -> cname.example.com -> 182.131.26.231

原始响应 (96字节):
  Header: 12字节
  Query: www.example.com (21字节)
  Answer1: CNAME cname.example.com (31字节)
  Answer2: A 182.131.26.231 (16字节)
  Answer3: A 5.6.7.8 (16字节)

数据结构:
  位置 0-11:   Header
  位置 12-32:  Query
  位置 33-63:  Answer1 (CNAME)
  位置 64-79:  Answer2 (A, 目标)
  位置 80-95:  Answer3 (A, 其他)

关键位置:
  位置42: Answer1头部的TTL最后一个字节 (0x2c)
  位置64: Answer2开始，压缩指针0xc02a -> 指向位置42

3. 修复方案
───────────
修改后的逻辑 (方案1: 保留CNAME链):

1. 遍历所有Answer，找到目标IP
2. 记录目标Answer之前的所有Answer（包括CNAME）
3. 保留这些Answer + 目标Answer
4. 更新ANCOUNT

代码实现:
```c
size_t keep_end_pos = pos;
int keep_count = 0;
int found = 0;

for (int i = 0; i < ancount && pos < *len; i++) {
    char domain[256];
    size_t answer_start = pos;

    if (parse_dns_name(data, *len, &pos, domain, sizeof(domain)) < 0)
        break;

    if (pos + 10 > *len) break;

    uint16_t rtype = read_uint16(data + pos);
    uint16_t rdlen = read_uint16(data + pos + 8);
    pos += 10;

    if (pos + rdlen > *len) break;

    /* 检查是否匹配目标IP */
    int match = 0;
    if (IP_IS_V4(best_ip) && rtype == DNS_TYPE_A && rdlen == 4) {
        ip_addr_t ip;
        IP_ADDR4(&ip, data[pos], data[pos + 1], data[pos + 2], data[pos + 3]);
        if (ip_addr_cmp(&ip, best_ip))
            match = 1;
    }

    if (match) {
        keep_end_pos = pos + rdlen;
        keep_count = i + 1;
        found = 1;
        break;
    }

    /* 如果是CNAME，继续保留 */
    if (rtype == DNS_TYPE_CNAME) {
        keep_end_pos = pos + rdlen;
        keep_count = i + 1;
    }

    pos += rdlen;
}

if (!found) return -1;

*len = keep_end_pos;
hdr->ancount = htons(keep_count);
```
