DNS响应修改修复验证报告
==========================

修复的函数: hev_dns_latency_modify_response() (src/hev-dns-latency.c:484-579)

修复前的问题:
-------------
1. 只保留目标Answer，删除所有其他Answer
2. 如果响应包含CNAME，CNAME被删除
3. 如果后续Answer使用压缩指针指向CNAME数据，压缩指针失效
4. 导致DNS客户端解析失败

修复后的逻辑:
-------------
1. 遍历所有Answer
2. 遇到CNAME时，记录位置继续遍历
3. 找到目标IP时，记录结束位置
4. 保留从开始到目标IP的所有Answer
5. 更新长度和ANCOUNT

关键代码:
---------
/* 如果是CNAME，继续保留（可能指向目标IP） */
if (rtype == DNS_TYPE_CNAME) {
    keep_end_pos = pos + rdlen;
    keep_count = i + 1;
}

/* 找到目标IP */
if (match) {
    keep_end_pos = pos + rdlen;
    keep_count = i + 1;
    found = 1;
    break;
}

/* 更新长度和ANCOUNT - 保留CNAME链 */
*len = keep_end_pos;
hdr->ancount = htons(keep_count);

修复效果:
---------

  原始: Header + Query + A1 + A(目标) + A3 + A4
  修复: Header + Query + A(目标)
  结果: ✓ 正确，无压缩指针问题

场景2: 有CNAME

  修复: Header + Query + CNAME + A(目标)
  结果: ✓ 正确，CNAME链保留，压缩指针有效

场景3: 有CNAME但Answer2指向Answer1数据
  原始: Header + Query + CNAME + A(目标) + A(其他)
  修复: Header + Query + CNAME + A(目标)
  结果: ✓ 正确，CNAME保留，Answer2的压缩指针仍有效
